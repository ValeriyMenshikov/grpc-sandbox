# Веб-фронтенд покупателя для gRPC-стенда (Vue 3)

## Overview

Добавляем веб-интерфейс покупателя в `frontend/` в корне репозитория. Стек: Vue 3, TypeScript, Vite, Vue Router; тесты на Vitest и Vue Test Utils; без UI-библиотеки. Сборка идёт в `node:22-alpine`, результат раздаёт `nginx:alpine`. nginx отдаёт SPA и проксирует `/api/*` на `${GATEWAY_URL}/*`, так что браузер ходит только на origin фронта и CORS не нужен. Фронтенд — отдельный сервис compose с healthcheck через busybox `wget`, порт на хосте `${FRONTEND_PORT:-3000}`, `mem_limit: 128m`.

Что умеет UI:
- вход, регистрация и экран подтверждения кода с подсказкой про `redis-cli`
- каталог с поиском, фильтрами (цена в рублях, в запросе копейки), сортировкой и курсорной пагинацией
- карточка товара
- корзина
- оформление заказа с переиспользуемым `Idempotency-Key`
- список заказов и страница заказа с поллингом статуса и прогрессом доставки
- единый разбор ошибок: rich details, 422, 401 (разлогин), 503/504

Бэкенд не трогаем. `make check`, `make test`, `make up`, `make down`, `make reset` работают как раньше. Проверки фронта — отдельными целями `make front-lint` и `make front-test`.

## Context

- Источник требований: `docs/stand/frontend-prompt.md`
- Контракты: `services/gateway/src/gateway/schemas.py` (JSON-модели), `services/gateway/src/gateway/errors.py` (тело ошибки, `WWW-Authenticate`), `services/gateway/src/gateway/routers/*.py` (пути и параметры), `docs/decisions.md` §16
- Сид-данные: продавец `seller@stand.local` / `seller-password` (users), товары и остатки в `services/catalog/src/catalog_service/schema.sql`. Политика order-service — `AuthPolicy.USER`, поэтому продавец тоже может пользоваться корзиной и оформлять заказы, и сквозной сценарий под сид-продавцом работает
- Файлы:
  - Create: `frontend/**`
  - Modify: `docker-compose.yml`, `.env.example`, `Makefile`, `.gitignore`, `README.md`, `docs/decisions.md` (новый пункт §27), `docs/stand/grpc-stand-TZ.md` (дерево каталогов), `CLAUDE.md`, `tests/smoke/test_smoke.py`
- Конвенции compose:
  - `<<: *restart`
  - порт внутри контейнера — литералом
  - адрес соседа — переменной с дефолтом `${VAR:-...}`
  - комментарий у `depends_on` («только порядок старта»)
- Подводные камни:
  - корневой `.gitignore` игнорирует `lib/` и `dist/`, поэтому каталог `frontend/src/lib` не заводим (код API — в `frontend/src/api/`)
  - `node_modules/` в `.gitignore` пока нет, его нужно добавить, иначе ruff и git его увидят
  - healthcheck фронта не должен зависеть от gateway и соседей, иначе `docker compose stop catalog` уронит фронт в unhealthy
- Зависимости (npm, точные версии фиксирует `package-lock.json`): vue, vue-router; dev: vite, @vitejs/plugin-vue, typescript, vue-tsc, vitest, @vue/test-utils, jsdom, eslint, eslint-plugin-vue, typescript-eslint, @vue/eslint-config-typescript

## Development Approach

- **Testing approach**: Regular (сначала код, потом тесты)
- Каждую задачу доводим до конца, прежде чем браться за следующую
- После каждой задачи: `make front-lint && make front-test`, плюс `make check && make test` (должны остаться зелёными), коммит `feat: ...` / `docs: ...`
- Логику (API-клиент, деньги, ошибки, авторизация, идемпотентность, поллинг) держим в чистых TS-модулях `frontend/src/api/` и composables. Тестируем их на Vitest с подменой `fetch`. Страницы тестируем через Vue Test Utils с замоканным API-модулем
- Комментарии на русском, тексты UI на русском
- Неочевидные решения записываем в `docs/decisions.md`
- **CRITICAL: every task MUST include new/updated tests**
- **CRITICAL: all tests must pass before starting next task**

## Post-Completion

- вручную: `cp .env.example .env && make up` — все контейнеры, включая фронтенд, `healthy`; открыть `http://localhost:3000`
- вручную в браузере: вход сид-продавцом → поиск → карточка → корзина → оформление → заказ доходит до `DELIVERED` без перезагрузки; повторный клик «Оформить» не создаёт второй заказ
- вручную: `docker compose stop catalog` → каталог показывает «сервис недоступен», а не белый экран
- `make smoke` и `make down && make up` — без ручных шагов
